# PaperDrama — PDF 论文转完整短剧脚本 Skill（v2.2.0）

**默认学术受众：非本领域大学生。默认媒介：竖屏 9:16 + 横屏 16:9 双画幅短剧。**

直接维护在 GitHub `main` 分支根目录。提交论文 PDF 并调用 `paperdrama-paper-to-drama` Skill 后，不需要用户提供任何关键词，即可运行第一阶段。展示三个方案后可**选择 A/B/C 或回复“换一波”生成新的一批**；用户未选择前不能越过创作决策直接输出最终剧本。

## 使用流程
**第一轮（自动分析，极简选项）：**
上传 PDF → 学术事实库（问题、矛盾、假设、方法、证据、结论、局限等）→ 戏剧化机会识别 → 内部 Drama Blueprint → **恰好 3 套极简短剧选项 A/B/C**。

**注意，三个选项展示时不提供任何具体剧情。每套只给：剧名、主题、设定、背景。** 例如展示形式（下列词仅演示格式，不代表默认剧情）：

```text
A｜《有戏剧张力的剧名》
主题：悬疑、科幻
设定：系统
背景：校园

B｜《另一个有戏剧张力的剧名》
主题：喜剧、脑洞
设定：灵魂互换
背景：职场

C｜《第三个有戏剧张力的剧名》
主题：权谋、悬疑
设定：强强联合
背景：架空

请选择 A、B 或 C；不满意可回复“换一波”。
```

**不展示**故事梗概、具体情节、人物、Hook、冲突细节、结局、集数、时长、论文结果、评分、受众或画幅介绍。这些分析内部可提前完成，但选定后才继续创作并揭示。

**不满意可换一波（新增）：** 用户只要回复“换一波”“再来三个”或“都不满意”，Skill 就复用同一论文事实库，生成一批真正不同的 A/B/C；不用重新上传 PDF，不用说明理由。可重复刷新多次。当前批次只展示剧名、主题、设定、背景及一句选择/刷新提示；旧批次内部存档，避免重复或选择错位。用户可默认从最新一轮选 A/B/C，或明确选择“第一波B”。选定后才开始写完整剧本。

## 两套必用的转译结构（新增）
详见 [Drama Blueprint](references/drama-blueprint.md)，新增的结构化字段与八类映射在**每套内部蓝图**中必须检验：

| Drama 表演要素 | 要求 AI 明确填写的内容 |
|---|---|
| 人物 | 角色数量、身份、目标、性格、人物关系 |
| 冲突 | 双方诉求、阻碍、矛盾升级方式 |
| 情节 | 起因、行动、意外、高潮、结果 |
| 情绪 | 好奇、紧张、怀疑、惊讶、释然（按情节调整） |
| 表演 | 对白语气、停顿、动作、表情、镜头 |
| 节奏 | 前几秒的钩子、关键转折点、集尾悬念 |

| 学术内容 | 对应短剧功能 |
|---|---|
| 研究背景 | 主角陷入困境，用具体事件开场 |
| 文献争议 | 双方观点对立、争论或辩论 |
| 研究假设 | 主角提出想法与挑战，不把假设讲成事实 |
| 研究方法 | 主角尝试验证，保留关键变量与方法 |
| 实验数据或其他证据 | 发现关键线索，数据必须准确 |
| 研究结论 | 真相揭晓或澄清，由结果决定剧情 |
| 研究局限 | 留下真实的疑问与边界 |
| 未来研究 | 合理的后续线索，只在原文支持时作为研究计划 |

两套结构用于**内部转译和最终剧本校验**，不扩展第一轮极简卡片的四个字段。论文中没有的元素须标记不适用，不得因表格要求而捏造争议、实验或结论。

**第二轮（用户选定后）：**
用户只回复 A/B/C → 完整剧集大纲 → 全部场景和完整对白 → 镜头/动作/音效/字幕 → 事实校验、戏剧校验、时长校验 → 输出 `full_script.md` 等文件。

**剧集与画幅**：集数与每集时长根据论文内容与演出密度确定，不固定。故事/对白用一套，每镜给出 `9:16` 与 `16:9` 两套构图和信息布局说明，避免只改画面比例却不调整视觉表达。用户如明确只要一种画幅，则按需生成一种。

## 叙事标签库
`references/narrative-library.md` 根据用户提供的参考图片整理 **4个维度83个标签，可自由组合**：28主题、42设定、11背景、2个可选内容受众标签。

“男频/女频”仅是可选的内容标签，**不能替代默认学术受众“非本领域大学生”**；选项展示只使用主题、设定、背景三个维度。

## 交付
- 第一阶段：`paper_facts.md`、`dramatic_opportunities.md`、`drama_blueprints.md`、`template_options.md`（最新一批）、`template_history.md`（内部历次方案记录）、`traceability_matrix.md`、`paperdrama.json`。
- 用户选定后：`series_outline.md`、`full_script.md`、`quality_report.md`，更新结构化数据与溯源。
- 资料不足或论文无法识别时须如实说明，不得补造实验事实；虚构人物与学术结果分开标注。

## 安装与复测
将本目录（包含 `SKILL.md` 及 `references/` 等）放到 Codex 支持的 Skill 目录并让宿主识别。用 `tests/acceptance-tests.md` 进行 A/B 选择、双画幅、事实性和交付完整性测试。写入 GitHub 不代表已在 Codex 中成功端到端执行。
