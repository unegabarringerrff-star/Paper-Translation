# 04 论文知识流与全貌解读｜新增规则

## 定位与不变项

`04 论文知识流与全貌解读.txt` 是**播放器侧栏的知识解释与观后补全内容合同**，不改变论文→主 Drama 锚点→世界规则→人物选择→场景脚本的叙事链。保持「一个主 Drama 锚点、最多两个辅助锚点」、原 `02 脚本.txt` 的场景模板、`03 剧情节点与论文原文.txt` 的证据对应条件不变。

- **02** 负责好看的非线性剧情，仍是唯一默认送入 MicroDrama 的文件。
- **03** 负责具体剧情触发与原文的完整可追溯对应，网页默认隐藏或提供下载，按需展开；不能为了补知识虚构剧情节点。
- **04-A** 负责观看中随剧情进展的低负荷微知识流。
- **04-B** 负责观看后整篇论文的结构化全貌解读，主动补足剧情钩子未覆盖的必要知识；不要仅重排 04-A。
- **00** 仍是全论文 fact_id、原文位置和必要限定的唯一事实基础。04 每个研究断言都要链接到已核验的 fact_id。

04 是独立的 UTF-8 TXT 文本文件；给网页消费的字段采用稳定的行标签与 ID。不输出 JSON、成片时码、前端代码或视频资产。原有「旧 04_连续性与交付核对.txt」已经归入 00，此新 04 与旧 04 的职责完全不同。

## 生成顺序｜先全貌，后同步

1. **全论文知识规划**：从 00 的事实表及已读论文建立覆盖全篇主线的「必要知识清单」。按研究类型自适应：研究动机/问题、数据或材料与方法（理论/设计/质性研究可替换为论证/过程）、主要发现或核心论证、结论与必要局限；不存在的维度标 `NOT_APPLICABLE`，不能虚构。
2. **知识原子化**：把具有独立信息价值的复合事实拆成微知识（例如参与者数量、分组、所测指标、结果方向和显著性分别为不同单元），每个单元可独立理解；同一 fact_id 可支持多个 knowledge_id，但不能以同义反复凑数量。保留样本/任务/范围/显著性/不确定性等影响正确理解的限定。
3. **建立联系**：将微知识归入有意义的 `theme_id`，并标出与前一知识的关系（背景、递进、补充、解释、对照、限定）；不要机械采用论文的 Introduction→Methods→Results 顺序作为视频播放顺序。
4. **核对剧情覆盖**：读取 02 的每集场次、主钩子、行动、转折、揭示时机，并使用 03 的真实触发节点（有则关联）。在内部比对「整篇必要知识」与「观看中自然可讲的知识」，把缺失部分分派到 04-B；**内部执行覆盖检查，但不要把独立的覆盖关系表作为 04 的第三个输出板块**。
5. **制作 04-A**：按剧情触发组织消息；可以先出现结果、后解释方法。以一行**陈述式知识标题**为默认；当剧情真正提出关键疑问时才用问句。核心概念、结果、纠偏可额外附一句短解释，普通微知识只输出标题。安排合理的显示节奏、知识主题、前后关系与具体 E##-S## 锚点。不要在反转前提前揭示谜底，不替虚构世界背书。
6. **制作 04-B**：将观看中出现过与未出现的必要知识合并为简明、连贯的论文全貌。观众应能回答「为什么研究、研究什么、怎么研究/论证、发现了什么、结论的边界是什么」。已展示内容简要回顾；未展示或仅部分展示的必要内容重点补全。每集可提供短小阶段回顾；**全剧结束**再提供覆盖整篇论文的总览，避免每集重复讲全篇。
7. **事实/负荷/对齐检查**：交付前依照 Gate D 检查 04-A/B 的事实、覆盖、重复、信息负荷、剧透与字段关联，未满足时定向返工 04，除非确有事实错误，不要为容纳知识而改写 02。

## 04-A｜实时微知识流

- 每个 `knowledge_id` 代表一个可独立核查、可独立阅读的微知识，至少关联一个 00 `fact_id`；一条可对应多个 fact_id，但都必须真实存在。
- 允许 `type=剧情关联` 或 `type=论文补全`。剧情关联型尽量关联现存 03 的 `PN-...` 节点；论文补全型可以只有 `fact_id`，`pn_id=NONE`，但仍需合适的 02 场景或过渡作为**显示位置**，不谎称它有 03 真实触发。
- 一集约 **2–4 个主题、7–9 条微知识/分钟**作为探索性设计目标，而非强制数量或固定每几秒弹出。根据论文事实密度、对白/字幕、情绪高潮、镜头与阅读时长减量、延后或转观后；不得造事实或机械拆句凑数。
- 一级「核心解释」：标题通常 8–16 个汉字，必要时加一条约 15–35 字的解释；二级「微知识」：原则上只有一句简明、肯定、准确的标题。以上为初始参考值，优先保证正确性与可读性；不可删去必要限定以卡字数。
- 一次只突出最新条目；上几条旧知识可保留短标题，较早条目可回看。同一主题下逐条累积，下一个主题开始时旧主题可折叠；用户不必主动点击下一条。
- 在剧情高潮、密集对白、重要字幕或视觉动作时允许不弹；对同一事件的连续知识建立可读的因果或解释关系，但不强迫观众理解孤立代词。
- 位置先写 `scene_id` 与**具体可识别触发动作/台词或相邻过渡**，再记录可选**预估相对时间区间**；成片需由播放器/下游重新校准。未经成片核对不写精确已验证秒点。
- 每条保存 `knowledge_id`、`theme_id`、`level`、`title`、`explanation`（若无写 NONE）、`relationship`、`fact_ids`、`scene_id`、`display_anchor`、`estimated_window`、`pn_id`（可空）、`source_location`、`reveal_policy`。多集 ID 用 `KC-E01-01` 格式且不得重复。
- `reveal_policy` 为 `即时解释` / `延迟揭示` / `独立补全`。延迟揭示必须在对应剧情信息已揭露后出现；独立补全不制造假的剧情对应关系。

## 04-B｜观后论文全貌解读

- **每集短回顾（可选）**：只回顾本集已介绍的主要知识及其与研究的关联，可提示仍有信息留待后续，不假装本集已经讲完整篇。
- **全剧最终全貌（必需）**：按论文类型整理完整知识脉络，包含必要的研究问题、证据/方法、发现/论证、结论与局限，严格以论文所支持的内容为准。使用紧凑明晰的小标题与短段落/要点，不复制 03 的原文。
- 每个概览单元包含 `overview_id`、`section`、`summary`、`fact_ids`、`display_status`；`display_status` 取 `已解释` / `部分解释` / `未解释`，由内部覆盖检查得出。后两类明确补全缺失部分；已解释项作简短回顾。
- 必须区分论文**真实结论**与剧情**虚构情节**；论文未证实的效果不得在总结中写成已证实。确无材料支持的项目写 `NOT_APPLICABLE` 或说明可读范围不足；如果缺失影响核心结论，按事实阻断规则处理。
- 04-B 可支持网页在视频结束后自动切换到「这篇论文讲了什么」的全貌结构，不强制弹出一篇长文章；让用户能迅速看到短剧未提到但必要的研究知识。
- 内部覆盖表仅供生成校核，不单独交付第三个表格/文件；在 04-B 单元中保留 `display_status`，在 04-A/B 保留事实证据 ID。

## 文件结构

`04 论文知识流与全貌解读.txt` **仅包含两个正文板块**：

```text
04-A｜实时微知识流
元信息：片名｜脚本版本｜论文标题｜已读范围｜时间状态=预计，成片需对齐
主题：theme_id｜主题名｜主题理解目标
集：E01｜目标时长｜知识条数
知识：KC-E01-01
  theme_id: ...
  level: 微知识 / 核心解释
  title: ...
  explanation: ... / NONE
  relationship: ...
  fact_ids: F...
  scene_id: E01-S01
  display_anchor: ...（确实存在的剧情或过渡）
  estimated_window: ...（预计；成片重对时）
  pn_id: PN-... / NONE
  source_location: ...
  reveal_policy: 即时解释 / 延迟揭示 / 独立补全
（其余条目同样格式；按实际各集顺序）

04-B｜观后论文全貌解读
本集短回顾：E01｜...（可选）
全剧论文全貌：
概览：OV-01
  section: 研究问题 / 方法或论证 / 发现 / 结论与局限 / 其他必要维度
  summary: ...
  fact_ids: F...
  display_status: 已解释 / 部分解释 / 未解释
（其余概览条目同样格式）
```

没有独立的「知识覆盖与补全关系」交付板块；生成时仍必须在内部完成覆盖核对。所有出现在网页上的研究表述都要可追溯，但 04 不重复 03 的逐字原文引用与剧情对照长文。
