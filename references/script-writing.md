# Script Writing & Production Rules｜PaperDrama 完整短剧脚本生成规范 v2.2

## 1. 只借鉴 PaperTok 的创作工作流，不搬它的表达
PaperTok 报告的系统流程可抽象成：识别可传播的研究内容 → 提供多个创意入口 → 用户选择并修改 → 生成脚本与媒介单元 → 分段编辑/生成 → 检查质量。
PaperDrama 使用同样的阶段协作逻辑，但叙事对象改为**有角色行动与因果冲突的短剧**，不使用 PaperTok 的固定八镜头、45秒结构、TikTok 风格科普话术或游戏背景。三个选项在 AI 内部是真正不同的短剧路线，**选择页对人只展示剧名、主题、设定、背景**，其余人物/剧情/集数/时长/Hook 均不可提前公开。用户选中后才进入全文。

## 默认画幅和受众
默认受众是**非本领域大学生**；默认输出同时适配 **9:16 竖屏**和 **16:9 横屏**两种短剧形式，共用一套论文事实、人物设定、对白和故事结构。

每个镜头除基础镜头说明外，必须分别给出：
- `vertical_9_16`：竖屏主体位置、近景/特写策略、表情重点、字幕及研究数据的竖屏安全区；
- `horizontal_16_9`：横屏角色空间关系、双人对话及环境信息、字幕/研究数据的横屏安全区。
不得只写“横屏版同上”“裁切成9:16”；图表与文字应有可读的尺寸和位置；复杂镜头要说明是否需要重新取景/重新生成素材。用户明确只要一种画幅时可只输出一种。

## 2. 先确认叙事轮次，落实六类表演语法与八类研究映射
- 用户可反复“换一波”，必须用**用户选定的批次 `selected_batch_id` + 该批次的 A/B/C** 查找详细蓝图，避免误把新一轮 A 配给旧一轮 A。
- 正式写剧集大纲前，检查 `characters`（角色数量、身份、目标、性格、关系）、`conflict`（双方诉求、阻碍、升级）、`plot`（起因、行动、意外、高潮、结果）、`emotion`（情绪节点）、`performance`（对白语气、停顿、动作、表情、镜头）、`rhythm`（开场钩子、关键转折、集尾悬念）。每项都需要具体可拍表现，不能只列关键词。
- 依据 `references/drama-blueprint.md` 的八类映射核对研究背景、文献争议、假设、方法、数据/证据、结论、局限、未来研究；对每项标记 `SUPPORTED` / `NOT_APPLICABLE` / `UNVERIFIED`，仅对有原文支持者落地学术剧情，未出现的研究活动不能伪造。
- 每场景对照 `fact_ids` 与演出动作；研究事实由结果/证据约束剧情而非相反。人物情绪可以戏剧化，但不能通过台词改变真实研究结论。

## 3. 从模板到可拍剧本
所选方案 → 剧集大纲 → 人物连续性圣经 → 具体场景 → 镜头节拍 → 完整对白/动作 → 音效/音乐/字幕 → 溯源与校验。
每集至少说明“这一集观众理解哪个学术问题/事实，以及故事怎样让他经历而非听讲这个知识”。
用能够被演员执行的动作、空间互动与冲突表达内容；禁止将论文朗读硬套成几个人的问答。

## 4. 每一集的写作格式
```markdown
# PaperDrama｜完整脚本
论文：...（作者、年份、来源文件）
选定模板：B（用户确认时间/语义）
总集数：N
各集时长：EP01 00:__；EP02 00:__；...
总时长：MM:SS
注：人物与演出片段为戏剧化改编；研究事实以引用为准

## 人物设定和演出原则
| 角色 | 立场/目标 | 人物弧线 | 关系 | 是否虚构 |

## EP01｜片名（MM:SS）
学术目标：... / 来源 fact_ids：...
剧情目标：... / 集末悬念或阶段收束：...

### Scene 1｜内/外 · 地点 · 时间 · 00:00–00:27（27秒）
场景目标：... 角色：... 研究锚点：[F001,F006]

| 镜头 | 时间码 | 9:16竖屏构图 | 16:9横屏构图 | 景别/运镜与场面 | 动作与表演 | 角色与完整台词/旁白 | 字幕/学术证据卡 | 声音（BGM/SFX/环境） | 事实ID与标记 |
| S01-SH01 | 00:00–00:06 | 人物面部居中，字幕底部安全区 | 人物居右，左侧环境补信息 | ... | ... | 角色：完整台词... | ... | ... | F001; FICTIONAL_DEVICE |
| S01-SH02 | 00:06–00:15 | ... | ... | ... | ... | ... | ... |

（完成所有场景和所有集，不得写“同上”“略”“后续自动生成”）

## 事实与虚构声明
- 本剧原文研究事实...
- 虚构人物/隐喻/桥段...
- 不能跨越的研究局限...
```

每镜头至少有时间码、9:16和16:9构图、景别/镜头运动、可见行为、全文对白或明确无对白、声音、事实映射。镜头不承载学术主张时可写 `source_fact_ids=[]` 和 `FICTIONAL_DEVICE`；不能使用它来掩盖事实性主张。

## 5. 控制时长
- 根据所需的知识节点和独立戏剧事件来定集数，再给每集计划时长。
- 每段对白按**中文约180–240汉字/分钟**粗估（仅为工作假设），另留自然停顿、转场、无对白表演时间；如果使用其他语言采用适当的语速估算。
- 镜头时间码从集内 `00:00` 单调递增、无缝连续或明确标识停顿/转场；不重叠也不空缺。
- `sum(shot.duration_s)=scene.duration_s`; `sum(scene.duration_s)=episode.duration_s`; `sum(episode.duration_s)=series.total_duration_s`。若数字不平，先修正后交付。
- 剧集数必须由内容密度决定；短论文可1集，信息丰富可多集。45–90秒仅为初始建议而不是硬性上限。

## 6. 事实审核卡
审查每个研究相关镜头：`episode/scene/shot → claim → fact_id → PDF页码/章节/图表 → 允许的简化与不可丢失的限定词 → PASS/REVIEW/FAIL`。
对“研究者真的说了这句话？”“被试真的做了这件事？”等需要认真区分：创作台词可由虚构角色讲，不能假称引述原话；用 `FICTIONAL_DEVICE` 告知观众是戏剧化演绎。
情节上的暴露/反转只能引用真实证据，否则让它成为“人物误解被澄清”，不是研究结果本身变了。

## 7. 脚本复审
- 情节：六类 Drama 语法（人物、冲突、情节、情绪、表演、节奏）均须体现到集/场/镜的具体动作；每一集有主体欲望、阻碍、行动、结果，前一集悬念得到解释。
- 学术：审查八类论文映射的来源状态与转译原则，重要条件、阴性结果、局限不丢；不存在虚构统计证据或没有来源的未来研究计划。
- 声画：同一人物稳定，画面可拍/可生成，声画时间可行，字幕与结论区别明确。
- 只要用户已选模板，就从大纲直接完成全部脚本与审查，不再以“确认这场/那个音效”为由中断。

## 8. 不要做的事
不要只输出三段梗概当作完整脚本；不要只写第一集；不要因为研究文献枯燥就把剧本改成纯科普脱口秀；不要只写人物念论文；不要将每一项科学数据都强行演成争吵；不要为剧集完整度补出论文没有的研究活动。
