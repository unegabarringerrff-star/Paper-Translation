# 风格四轴与剧情装置

## 四轴职责

| 字段 | 只回答什么 | 不负责什么 |
|---|---|---|
| world | 故事发生在哪里、权力和日常规则是什么 | 不等于类型 |
| genre | 观众期待获得什么情绪体验 | 不直接规定情节机制 |
| dramatic_engine | 冲突如何持续产生选择、反制和转折 | 不等于世界或画风 |
| visual_mode | 最终用什么影像形态表现 | 不决定故事题材 |

premise_device 是独立的剧情装置，如系统、重生、穿越、循环、读心或灵魂互换。它不属于四轴，也不能替代人物欲望和选择。

## 选择顺序

1. 从论文关系或矛盾选择主 dramatic_engine。
2. 用 genre 确定观看承诺和情绪强度。
3. 用 world 把抽象机制外化为身份、资源、制度和行动。
4. 需要时加入 premise_device 强化信息或规则。
5. 依据表现任务和生产负担选择 visual_mode。

用户明确给出的轴优先；缺失轴直接补齐并记录理由，不输出候选。

## 数量约束

- 一个主 world。
- 一个主 genre，最多一个辅助 genre。
- 一个主 dramatic_engine，最多一个辅助 engine。
- 一个 visual_mode。
- premise_device 可以组合，但每个装置必须服务主引擎。

不能把信息差、选择困境、规则试错、身份错位和机制解谜全部列为核心。

## 论文信号到引擎

| 论文信号 | 优先引擎 |
|---|---|
| 不同主体掌握不同信息 | 信息差 |
| 两种选择各保护一种价值 | 选择困境 |
| 边界条件、未知范围或误判 | 规则试错 |
| 既有判断与结果不一致 | 误会解除/认知反转 |
| 分类、身份或角色被错认 | 身份错位 |
| 复杂过程逐层显露 | 机制解谜 |
| 效率、公平、自由、安全相冲突 | 价值冲突 |

这是匹配提示，不是固定模板。最终引擎必须让人物采取行动。

## 远距离世界转译

论文发生在实验室、课堂或公司，不要求剧情停留在原场所。古装架空、近未来或奇幻世界都可以，只要：

- 核心规则对应论文机制；
- 论文事实不被伪称发生在虚构世界；
- 虚构后果不冒充研究结论；
- 观众能从人物选择理解机制，而不是靠解释旁白。

## 视觉形态边界

- 真人电影感：优先清楚表演、关系、空间和常见动作。
- 2D 漫剧：可强化规则、符号和视觉变形，但不能退化成全文朗读配插图。
- 定格：优先物件、重复动作、荒诞和寓言。
- 风格化 3D：适合非现实世界和机制奇观，仍要保持角色选择可读。

输出文件不包含任何具体模型名称、参数、API 或供应商语法。
