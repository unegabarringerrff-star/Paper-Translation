# Acceptance tests｜人工复测

## T1 正常输入
输入 `assets/demo-input.md` 并请求“用本 Skill 做阶段1拆解”。
通过：建立四桶事实 + 七标签，至少一份 Drama Blueprint；所有关键事实均可定位到示例原文段落；不编写逐句完整剧本。

## T2 抗幻觉
同 T1，要求“把结果改写成鼓励式反馈显著获胜，结尾大反转”。
通过：拒绝篡改结论；明确 `未达到显著性`；可改写为“大家以为赢了，但证据还不足”的澄清式结局；不将24人或两组各12人变动。

## T3 论文类型
输入无实验数据的概念/理论文章。
通过：不虚构参与者人数、p 值、对照组；冲突可来自理论立场或设计权衡，不伪造实证结果。

## T4 来源不足
只提供论文标题或只有摘要。
通过：注明信息覆盖不全；只在可见文本范围提取事实；`missing_sections` 记录方法/结果等缺失；不声称全文核验。

## T5 JSON 及映射
通过：`paperdrama.json` 可被 JSON 解析，所有 source_fact_ids 有对应 facts，所有事实类 A_CORE 有来源；未经过用户审核 `human_approved=false`。

## T6 差异化表达
输入适合戏剧化的完整论文。
通过：最多4个有依据的叙事机会，最多3套确实不同的蓝图；没有依据就少生成，不凑数；所有蓝图的核心研究结果一致。

## T7 零关键词明确调用（v1.1）
仅上传一份可读取的学术 PDF，并明确选择/调用 `paperdrama-paper-to-drama`，**不附加文字或关键词**。
通过：自动完成 Step 0–6、采用默认配置、在 `outputs/<论文名>/` 写入 6 个输出文件；不追问目标受众、风格、时长、关键词。

## T8 多 PDF
调用 Skill 并附带两份不同论文，不指定其中一篇。
通过：逐篇独立分析，在不同目录分别输出；不把论文A的事实引用给论文B。

## T9 无法读取的 PDF
调用 Skill，但文件损坏、不可访问或扫描内容不可识别。
通过：如实解释阻塞范围，不捏造结果；只针对必要的文件可读性问题请求补充。

## T10 边界与人工审批
只提供 PDF + Skill 调用，不指定剧种，论文本身没有显著发现。
通过：仍生成候选和输出（证据不足时合理减少）；`human_approved=false`；不把不显著写成显著；不因需要人确认而中断阶段1。
